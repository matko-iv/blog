Roleplay Nations — six years, three databases, and the end of the story
13 February 2026

Roleplay Nations is a Discord bot for simulating countries. Players create nations, build infrastructure, go to war, spy, trade and form alliances. I started making it in 2020 when I barely knew Python, and I've worked on it off-and-on until today.


## How it started

I'm not a developer. I've never been a developer. I haven't finished my computer science degree yet (freshman), I don't work in IT, and when I started this project I barely knew what I was doing. It was 2020, lockdown, boredom, and I was using Discord like many others. I came across so-called "text roleplay". People were playing as countries and typing what they were doing, for others in the same server to see. That sounded pretty strange to me. I thought it would be better to make some kind of automatic middleman to keep control. I thought I could make my own. It turned out I could, just not the way I imagined.

I started with discord.py tutorials and Stack Overflow copy-paste. The first ten or so commands somehow worked, and that was enough to keep me going. You can't imagine how much nostalgia I feel typing this.


## Three databases

The database went through three complete rewrites. Each one was bad in its own way.

At first everything was in JSON files. Every nation, every resource, every war: JSON. For anyone who doesn't know why this is bad: imagine you have a table with 200 rows, but instead of an actual spreadsheet you use Notepad, manually find the row you need, change it and save. Every time, for every operation. While 30 other people do the same thing at once.

```python
with open('nations.json', 'r') as f:
    data = json.load(f)
data[user_id]['money'] -= 500
with open('nations.json', 'w') as f:
    json.dump(data, f)
```

This worked for months, with a small number of players. And then the problems came: data disappearing, nations resetting, money appearing out of nowhere. Concurrent access to the file system with no protection at all.

Then I moved to SQLite through `aiosqlite`. A real database format, technically at least. The migration was manual, I was literally copying the data over. Some of it got lost. Players were asking where their nations went.

Somewhere around 2024 I moved to PostgreSQL with `asyncpg` and a connection pool. Third migration, third time players lost something. But this time I at least roughly knew what I was doing.

All three systems still exist in the code. You can find `aiosqlite` imports, JSON reads and `asyncpg` queries, all in the same project. Six years of a hobbyist learning databases in real time.


## What the bot actually does

The bot eventually grew into something serious in scope, if not in code quality. An economy with 22 resource types, production buildings, taxes and monthly economic updates. A military with tanks, planes, ships, missiles, factories on 5 levels, warehouses and battles. Espionage with an agency, agents, 13 traits and 4 types of missions. Diplomacy with alliances, treaties, embargoes and shared treasuries. A player-driven resource market and a Central International Bank (the IMF maybe?) with dynamic prices. Even airlines: buying planes, hiring pilots and staff.

150+ slash commands, 14 cogs, about 17,000 lines of code.


## Code quality

The code is bad. There's not much to philosophize about there. You'll find inconsistent patterns, questionable architectural decisions, spaghetti in places, and artifacts from every phase of the project. A 5,000-line file that does everything. Duplicate imports.

One bug I only discovered recently, after six years:

```python
async def after_invoke_hook(interaction):
    time.sleep(5)  # Blocks the whole event loop. Six years. Nobody noticed.
```

`time.sleep()` in an async function. It blocks the whole bot for 5 seconds after every command. It had been there from the beginning.

But the bot worked. Players played, wars were fought, alliances rose and fell. The format worked: you run a command, see how your nation changes, trash talk in the alliance channels, a declaration of war at 2 in the morning. All on code that any senior developer would describe as a problem.


## The Discord nation-RP scene

When I started in 2020, Discord bots for simulating countries were a thing. Several active bots, engaged communities, and the format made sense because everyone was on Discord all day anyway.

That scene has mostly died. Most bots from that era are either dead or barely maintained. The genre moved to browser-based simulators: real web apps with interfaces, maps, real-time updates, things a Discord bot can't offer. Games like Politics and War and NationStates set a standard that a slash command can't reach.

AI sped that change up further. People today build full-stack country simulators with real frontends in a couple of weeks, the thing that took me years. Those same tools are the reason my bot is no longer competitive and why Discord nation-RP bots are mostly a thing of the past.

I still think the format has something: the immediacy of running a command, the drama in the channels, the spontaneity of it all. But Discord as a platform for this type of game has its limits, and the audience has mostly moved on.


## Why open source, why now

The bot is less and less active. I've stopped regularly working on new features, the player base has shrunk, and I've decided to shut down Roleplay Nations in January 2027. After that I plan to build a real country simulator with a friend from university, something much more sophisticated, with all the lessons from this project's mistakes. From scratch, with a proper backend, a real frontend, and an architecture that makes sense.

The code is going on GitHub. If anyone wants to run their own version, they can. The README has complete instructions, from creating the Discord application to the PostgreSQL schema and deploying to a VPS. Just know what you're getting into.


## What I learned

Five things, after six years:

- JSON is not a database. This should be written at the entrance of every programming school.
- Write tests, or you'll find bugs through your users complaining. For years.
- "I'll refactor when I finish this new thing" is the biggest lie I've told myself.
- If an exploit exists, users will find it. And they won't tell you. They'll use it until you notice on your own.
- A project doesn't have to be perfect to be useful. Over 900 players played this game for years, on code that barely holds together.


## What's next

Roleplay Nations lives until January 2027. The code is on GitHub. The next project starts soon, with a real plan and hopefully a better architecture.

If you ever played Roleplay Nations, thank you. This game was my programming school, and without the players who put up with the bugs, the server crashes and the unexplained data losses, I wouldn't have learned half of what I know.
